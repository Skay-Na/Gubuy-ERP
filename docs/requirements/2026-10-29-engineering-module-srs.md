## 1. 背景与目标

### 1.1 背景

现有系统只服务**零售单**：门店开单 → 收银 → 国补核销 → 安装送货。近半年出现一类完全不同的业务——**工程机（工程项目）批量供货**：

- 客户是开发商、物业、酒店、学校、装修公司、政企单位，不是个人消费者；
- 一次采购几十到几百台，按项目清单报价，单价低于零售价；
- 周期长（1~12 个月），分批送货、分批安装、**按合同节点分期收款**（预付款 / 到货款 / 验收款 / 质保金）；
- 回款风险高，必须盯节点、盯逾期。

这类业务目前被塞进零售开单流程，导致三个实际痛点：

1. **一张订单开不出一个项目**：几十台设备拆成 N 张零售单，项目总额、项目毛利、项目进度无法汇总；
2. **分期收款无处登记**：零售单只认"定金 + 尾款"，工程款的付款节点（30/60/10）在系统里无法表达，老板只能靠 Excel 记账；
3. **口径污染**：工程单混进零售统计，单均、毛利率、员工业绩全部失真。

### 1.2 目标

| 编号 | 目标 | 可量化验收 |
| --- | --- | --- |
| G1 | 一个工程项目 = 一个档案 | 项目主档可承载合同额、清单、回款、发货全信息，不再拆单 |
| G2 | 分期回款可视可跟踪 | 待回款、逾期节点、逾期金额在列表页一屏可见 |
| G3 | 项目净利算得清 | 合同总额 − 设备成本 − 工程费用（实际支出），实时可查；费用逐笔可追溯到类别、收款方、日期 |
| G4 | 库存账实一致 | 工程出库写库存流水（新类型 `engineering`），库存流水页可审计 |
| G5 | 零售口径零污染 | 工程数据不进零售订单表、不进国补、不进经营看板与工资条 |
| G6 | **工程开销独立成账** | 工程费用有独立录入入口、独立分类、独立汇总；不与日常「经营开销」混记，不写入 `financial_logs`、不改变任何账户余额 |

### 1.3 成功标准（上线后 1 个月）

- 全部在跟工程项目在系统内有档案，Excel 台账下线；
- 待回款金额与老板人工台账差异为 0；
- 零售看板的单均、毛利率无异常波动（工程数据未串入）。

## 2. 范围界定

### 2.1 业务定义（重要）

本模块的"工程"= **工程机业务 / 工程项目批量供货**，即面向 B 端单位的招投标、批量采购、分期回款类项目。

> 假设说明：若"工程"实际指**施工/安装派工管理**（把安装师傅的工序、工时、验收单管起来），则本说明书整体不适用，需重写。请在确认环节明确。

### 2.2 范围内（MVP，本期必做）

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| F1 | 工程项目列表 | 筛选、搜索、状态标签、顶部汇总卡 |
| F2 | 项目主档建档/编辑 | 甲方信息、项目信息、金额、负责人 |
| F3 | 设备清单 | 选商品、数量、工程单价、成本快照、行小计与毛利 |
| F4 | 合同与付款节点 | 合同额自动合成、付款节点计划（金额 + 计划日期） |
| F5 | 回款登记 | 按节点登记实收，支持部分收款、累计校验 |
| F6 | 工程出库 | 按清单行出库，扣库存、写库存流水 |
| F7 | 项目详情页 | 概览 / 清单 / 回款 / 出库 / **费用** 五个分区 |
| F8 | 项目统计 | 在跟额、已签约额、待回款、逾期金额、本年实收 |
| F9 | 状态流转与作废 | 五态状态机 + 软删除 + 作废留痕 |
| **F10** | **工程费用管理** | 按项目逐笔录入实际支出（安装人工 / 运输 / 辅材 / 现场 / 差旅 / 外包），七类分类汇总，用于算项目净利 |
| **F11** | **工程费用台账** | 跨项目查看全部工程开销、按类别分布、录入不分摊到项目的公共费用 |

### 2.3 范围外（本期明确不做）

| 不做的事 | 理由 |
| --- | --- |
| 国补相关一切（补贴金额、补贴状态、回款核销、国补台账） | 工程机不属于以旧换新补贴范围，硬性解耦 |
| 员工端（`/terminal`）任何入口与接口 | 本模块只在管理端后台 |
| 零售订单表 `orders` 写入 | 工程单独立建表，绝不与零售单混存 |
| 业务提成计算、工资条联动 | 与商会订单规则交叉风险高，二期再议（见 Q4） |
| 资金账户余额变动、公户流水 | 一期只做项目维度应收/实收台账（见 Q1） |
| **工程费用同步记入「经营开销」账户（id=7）** | 用户明确要求：**工程开销与日常经营开销必须分开，不能混在一起**。工程费用只在工程模块内独立核算，禁止在经营开销账户再记一遍（否则重复计成本、毛利双算） |
| **日常经营开销记入工程费用** | 反向亦然。工程费用只收项目相关支出，公司日常开销（房租、水电、加油、请客）走原「经营开销」账户 |
| 经营看板 / 净利润口径接入 | 见 Q2 |
| AI 店长数据工具接入 | 一期不做，二期按需开放只读工具 |
| 投标管理、竞争对手报价、报备审批流 | 一期五态足够，避免过度设计 |
| 合同附件上传、电子签章 | 一期用"合同编号 + 备注"承载 |
| 打印报价单 / 合同模板输出 | 二期（先确认是否真要） |

### 2.4 与既有模块的边界（必须遵守）

| 既有模块 | 关系 | 约束 |
| --- | --- | --- |
| `orders` / `order_items` | **不写、不读** | 工程数据独立成表；零售列表、记账、收银均不受影响 |
| 国补（`subsidy_*`） | **零关联** | 工程模块无任何补贴字段、无补贴状态机 |
| 库存（`products.store_stock` / `inventory_logs`） | **只扣减 + 写流水** | 新增 `log_type='engineering'`；出库必须留流水，禁止静默改库存 |
| 资金账户（`accounts` / `financial_logs`） | **一期不动** | 见 Q1；若确认要进公户，另行追加设计 |
| 经营开销账户（`accounts` id=7） | **不写、不混** | 工程费用独立成表 `engineering_expenses`，**禁止**再写入经营开销流水；页面上双向提示，避免老板重复录 |
| 经营看板 / 净利润 | **一期不动** | 见 Q2 |
| 工资条 / 提成 | **一期不动** | 工程单不产生 `commission_amount` |
| 操作历史（`operation_histories`） | **接入** | 增删改一律留审计快照，与现有一致 |
| 员工管理（`employees`） | **只读引用** | 项目负责人 / 安装负责人下拉复用员工列表 |

## 4. 业务流程

### 4.1 项目生命周期（状态机）

```
        ┌──────────┐  填合同额+付款节点   ┌──────────┐  首次出库  ┌──────────┐
        │ 1 跟进中 │ ──────────────────▶ │ 2 已签约 │ ─────────▶ │ 3 供货中 │
        └──────────┘                     └──────────┘            └──────────┘
             │                                │                       │
             │                                │        全部发货+人工确认验收
             │                                │                       ▼
             │                                │                 ┌──────────┐
             │                                │                 │ 4 已验收 │
             │                                │                 └──────────┘
             │                                │                       │ 应收全部收齐（自动）
             │                                │                       ▼
             │                                │                 ┌──────────┐
             │                                │                 │ 5 已结清 │
             ▼                                ▼                 └──────────┘
        ┌──────────────────────────────────────────┐
        │ 9 已作废（任意状态可作废，需填原因，留痕） │
        └──────────────────────────────────────────┘
```

状态规则：

| 状态 | 值 | 进入条件 | 允许的下一步 |
| --- | --- | --- | --- |
| 跟进中 | 1 | 建档默认 | 2 已签约 / 9 作废 / 删除（软删） |
| 已签约 | 2 | 合同总额 > 0 且付款节点合计 = 合同总额 | 3 供货中 / 9 作废 |
| 供货中 | 3 | 首次出库成功（自动） | 4 已验收 / 9 作废 |
| 已验收 | 4 | 所有清单行"已发货数量 = 订购数量" 且 人工填验收日期 | 5 已结清（自动） / 9 作废 |
| 已结清 | 5 | 已实收合计 = 合同总额（自动触发，同时写结清时间） | 终态（仅可查看） |
| 已作废 | 9 | 任意状态 + 作废原因（≥5 字） | 终态 |

**回退规则**：状态允许"回退一步"，需管理员二次确认并写审计（例：已签约 → 跟进中；供货中 → 已签约，仅当无出库记录）。已结清不可回退。

### 4.2 回款流程

1. 签约时录入 N 个付款节点：`节点名称 + 计划比例 或 计划金额 + 计划日期`；
2. 到账后进项目详情"回款"分区，选择节点 → 登记实收（金额、到账日期、收款方式、备注）；
3. 同一节点可多次登记（部分收款），节点累计实收 > 计划金额时**拦截**，提示"请先调整该节点的计划金额"；
4. 项目实收合计达到合同总额 → 自动置"已结清"并写结清时间；
5. 节点实收 < 计划金额 且 计划日期 < 今天 → 标记"逾期"，列表页与详情页红色标识。

### 4.3 出库流程

1. 进入项目详情"出库"分区，按清单行填写本次出库数量（≤ 订购数量 − 已发货数量）；
2. 选择发货仓（门店 / 云仓代发）；
3. 提交 → 扣减 `store_stock`（云仓代发扣 `cloud_stock`）+ 写 `inventory_logs`（`log_type='engineering'`，`related_no=项目编号`）+ 累加行的 `shipped_qty`；
4. 首次出库成功后项目自动进入"供货中"。

## 5. 功能需求

### F1 工程项目列表

**入口**：管理端侧边栏「工程」→ `/admin/engineering`

**顶部汇总卡（6 张）**

| 卡片 | 口径 |
| --- | --- |
| 在跟项目 | 状态 ∈ {1,2,3} 的项目数 + 合同额合计（状态 1 无合同额按设备总额估） |
| 待回款 | Σ(合同总额 − 已实收) ，仅状态 ∈ {1,2,3,4} |
| 逾期金额 | Σ(逾期节点计划金额 − 该节点已实收) |
| 本年实收 | 本自然年回款记录合计 |
| **本年工程开销** | 费用发生日期在本年的**全部**费用合计（项目费用 + 公共费用），含已付与未付 |
| 平均净利率 | Σ(合同额 − 设备成本 − 该项目费用) / Σ合同总额（仅状态 ≥2，不含公共费用） |

**列表列**：项目编号｜项目名称｜甲方单位｜项目类型｜负责人｜合同总额｜已回款｜待回款｜整体进度｜状态｜最近更新

- 「合同总额」单元格下方以 11px 小字显示 **净利率**（如 `净利率 16.2%`，负值红色），不单独占列，避免表格过宽；未签约项目显示 `—`。

- 回款进度用进度条 + 百分比（已实收 / 合同总额）；
- 状态用彩色标签（跟进中=灰、已签约=蓝、供货中=橙、已验收=紫、已结清=绿、已作废=浅灰删除线）；
- 逾期行整行或"待回款"单元格红色高亮。

**筛选**：关键词（项目名称 / 编号 / 甲方 / 联系人 / 电话 模糊）｜状态（多选）｜项目类型｜负责人｜签约日期区间｜只看逾期（开关）

**排序**：最近更新（默认倒序）｜合同额｜待回款｜计划回款日

**分页**：默认 20 条/页，可选 20/50/100。

**验收标准**
1. 汇总卡数字与列表筛选结果一致性可通过 SQL 复核；
2. 切换筛选后汇总卡随筛选联动（或明确标注"汇总为全量口径"——实现时二选一，设计阶段定）；
3. 逾期项目在列表中可被"只看逾期"精确筛出；
4. 空态有引导文案与"新建工程"按钮。

### F2 项目主档建档 / 编辑

**入口**：列表页「新建工程」按钮 / 行内「编辑」

**字段清单**

| 分组 | 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| 基本信息 | 项目编号 | 文本 | 是 | 自动生成 `GC-YYYYMMDD-序号`，可手改但需唯一 |
| | 项目名称 | 文本(100) | 是 | 如"XX 花园 3 期精装房空调工程" |
| | 项目类型 | 单选 | 是 | 1 住宅精装 / 2 商业综合体 / 3 酒店公寓 / 4 政企学校 / 5 其他 |
| 甲方信息 | 甲方单位 | 文本(150) | 是 | 如"XX 置业有限公司" |
| | 甲方联系人 | 文本(50) | 是 | |
| | 联系电话 | 文本(20) | 是 | 手机号或座机，格式校验 |
| | 项目地址 | 文本(255) | 否 | 送货地址默认取此值 |
| 商务信息 | 销售负责人 | 员工下拉 | 是 | 引用 `employees`，含外包人员 |
| | 预计合同额 | 金额 | 否 | 跟进中阶段的预估，仅供汇总 |
| | 签约日期 | 日期 | 否 | 状态 ≥2 时必填 |
| | 合同编号 | 文本(50) | 否 | 甲方合同号 |
| 其他 | 备注 | 文本(500) | 否 | |

**规则**
- 项目编号唯一，重复时拦截并提示已占用编号；
- 删除仅允许"跟进中 + 无回款 + 无出库"的项目，且为软删除（`deleted_at`）；
- 编辑已结清项目：仅允许改备注与联系人电话，金额类字段锁定。

**验收标准**
1. 必填校验前端 + 后端双重拦截，后端返回 code 400 + 明确字段提示；
2. 项目编号并发创建不重复（唯一索引兜底）；
3. 建档后立刻出现在列表首位（按更新时间倒序）。

### F3 设备清单

**位置**：项目详情「设备清单」分区；建档后即可编辑

**行字段**

| 字段 | 说明 |
| --- | --- |
| 商品 | 从商品库选择（搜索名称/备注），显示当前库存与零售价做参考 |
| 数量 | 正整数，≥1 |
| 工程单价 | 手工录入（不受零售价约束，可低于特价） |
| 成本单价 | **默认取商品 `avg_cost` 快照，可手改**；落库快照，后续商品改价不影响历史 |
| 行金额 | = 数量 × 工程单价（只读） |
| 行成本 | = 数量 × 成本单价（只读） |
| 行毛利 / 毛利率 | 只读，负毛利行标红警告（不拦截） |
| 已发货数量 | 只读，由出库动作累加 |
| 备注 | 如"含 3 米铜管加长" |

**汇总条**：设备总额、设备总成本、设备毛利、毛利率

**规则**
- 同一商品可多行（不同单价/备注），不做合并去重；
- 数量改小于已发货数量时拦截；
- 清单为空时不允许签约（状态 2）。

**验收标准**
1. 修改数量/单价后汇总条实时更新，与手算一致（保留 2 位小数，四舍五入）；
2. 成本单价默认值取 `avg_cost`，商品无成本（=0）时行内提示"成本缺失，毛利虚高"；
3. 已产生出库的行，商品不可替换。

### F4 合同与付款节点

**合同金额合成（只读计算，避免手填飘数）**

```
设备总额  = Σ(数量 × 工程单价)          ← 清单自动
安装费    = 手工录入（默认 0）
运输费    = 手工录入（默认 0）
其他费用  = 手工录入（默认 0）
折让      = 手工录入（默认 0，正数表示让利）
──────────────────────────────────
合同总额  = 设备总额 + 安装费 + 运输费 + 其他费用 − 折让
```

**付款节点表**

| 字段 | 规则 |
| --- | --- |
| 节点名称 | 如"预付款""到货款""验收款""质保金"，可自定义 |
| 计划比例(%) | 与计划金额二选一，填比例自动算金额 |
| 计划金额 | 金额，2 位小数 |
| 计划日期 | 日期，用于逾期判断 |
| 累计实收 | 只读，由回款记录汇总 |
| 状态 | 未收 / 部分收 / 已收 / 逾期（自动派生，不落库或落库均可） |

**规则**
- 节点计划金额合计 **必须等于** 合同总额，不等时不允许签约（提示差额，附"按比例自动补齐"按钮思路由设计阶段定）；
- 节点数量 1~12 个；
- 签约后新增节点需二次确认，且会解除"已结清"判定；
- 质保金类节点允许计划日期为签约后 N 个月。

**验收标准**
1. 合同总额随清单与费用项变动实时重算；
2. 节点合计 ≠ 合同总额时，签约按钮置灰并提示差额具体数字；
3. 调整合同总额后，若节点合计不符，给出明确提示而非静默通过。

### F5 回款登记

**入口**：项目详情「回款」分区「登记回款」

**字段**

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 付款节点 | 是 | 下拉，仅本项目节点 |
| 实收金额 | 是 | > 0，≤ 该节点剩余应收 |
| 到账日期 | 是 | 默认今天，不可晚于今天 |
| 收款方式 | 是 | 1 银行转账 / 2 承兑汇票 / 3 现金 / 4 支票 / 5 其他 |
| 票据号 / 流水号 | 否 | 承兑汇票建议填，文本(50) |
| 凭证备注 | 否 | 文本(200) |

**规则**
- 支持部分收款，节点累计不得超过计划金额（超额拦截，见 Q1 关于"提前收款/超收"的处理）；
- 项目累计实收不得超过合同总额；
- 回款记录**不可编辑金额**，只能"冲销"（新增一条负数记录并注明原因），冲销需管理员确认 + 审计留痕——与现有退款红冲思路一致；
- 回款登记成功即时刷新列表与详情的待回款。

**验收标准**
1. 超额登记被拦截，提示"该节点剩余应收 ¥X"；
2. 冲销后节点与项目待回款同步恢复；
3. 所有回款记录在操作历史中可查（谁、何时、金额、原因）。

### F6 工程出库

**入口**：项目详情「出库」分区「出库」按钮

**字段**

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 清单行 | 是 | 多行勾选，每行填本次数量 |
| 本次数量 | 是 | 1 ~ (订购数量 − 已发货数量) |
| 发货仓 | 是 | 门店 / 云仓代发 |
| 出库日期 | 是 | 默认今天 |
| 物流单号 / 备注 | 否 | |

**规则**
- 扣库存：门店仓扣 `store_stock`，云仓扣 `cloud_stock`；
- 库存不足时：提示"门店库存不足（现 X 台），是否继续出库并允许负库存？"——**需管理员二次确认**，允许负库存是为了工程先供货后补货的真实场景；
- 每次出库写 `inventory_logs`：`log_type='engineering'`、`warehouse_type` 对应仓、`related_no=项目编号`、`remark` 含项目名与本次出库序号；
- 出库记录本身也要可查（项目详情内出库明细：时间、商品、数量、仓、操作人）。

**验收标准**
1. 出库后商品库存精确减少，库存流水页可见 `engineering` 类型并可筛选；
2. 出库数量超订购量被拦截；
3. 允许负库存时写清审计备注，便于事后核对。

### F7 项目详情页

**布局**：顶部项目头（名称 + 编号 + 状态标签 + 甲方 + 三个关键数字：合同总额 / 已回款 / 待回款）+ **五个**分区 Tab：

1. **概览**：基本信息卡、金额构成卡（设备/安装/运输/其他/折让 → 合同额）、**盈利卡（设备成本、工程费用、净利、净利率）**、进度条（回款进度 + 发货进度）、下一步建议文案（如"3 个节点已逾期，合计 ¥120,000"）
2. **设备清单**：F3
3. **回款**：付款节点表 + 回款记录表 + 登记按钮
4. **出库**：出库明细表 + 出库按钮
5. **费用**：F10 工程费用明细 + 分类汇总 + 录入按钮

**验收标准**：五个分区数据互相一致（清单总额 = 概览设备总额；节点合计 = 合同总额；发货合计 ≤ 订购合计；费用 Tab 合计 = 概览工程费用 = 净利扣减额）。

### F8 项目统计

**位置**：列表页顶部汇总卡（同 F1）+ 可选的「工程分析」小页（二期）

**一期口径**（明确写死，避免歧义）：
- 在跟额：状态 1/2/3 的合同总额（状态 1 用预计合同额兜底）
- 待回款：Σ(合同总额 − 实收) ，状态 1~4
- 逾期金额：逾期节点未收部分之和
- 本年实收：`payment_date` 在今年的回款合计
- **本年工程开销**：费用 `expense_date` 在今年的合计（项目费用 + 公共费用，已付未付都算）
- **平均净利率**：仅统计状态 ≥2 的项目，Σ(合同额 − 设备成本 − 该项目费用) / Σ合同额；**不含公共费用**（公共费用没有项目可摊，强行分摊会让每个项目净利都不准）

**验收标准**：所有数字可被一条可复述的 SQL 复算，口径写进文档与页面 tooltip。

### F9 状态流转与作废

- 状态流转按 4.1 状态机，非法流转后端拦截（code 400）；
- 作废：任意状态可作废，必填原因（≥5 字），作废后：
  - 不再进入任何统计；
  - 已出库的不自动退库，需人工走"入库/调拨"补回（二期可做"作废自动退库"，见后续规划）；
  - 已回款记录保留，需人工线下处理退款；
- 删除：仅"跟进中 + 无回款 + 无出库"，软删除。

**验收标准**：作废项目在默认列表隐藏（可通过"含作废"开关查看），汇总卡不计入。

### F10 工程费用管理（v1.1 新增）

**为什么单独立账**：现有系统把所有非进货成本的花销统一记「经营开销」账户（`account_id=7`）。工程业务的支出结构完全不同——安装人工、吊装、辅材、外包施工队，一笔动辄几万，且必须归集到具体项目才能算清项目赚不赚钱。混进日常开销后：① 项目净利算不出；② 日常开销被工程款冲高，看经营费用率失真；③ 老板分不清"这个月钱花在哪"。

**因此**：工程费用**独立成表**（`engineering_expenses`）、**独立分类**、**独立汇总**，一期不写 `financial_logs`、不改任何账户余额。

#### F10.1 口径定义（全模块唯一口径，禁止各处自算）

```
设备毛利  = 合同总额 − 设备成本合计            ← 只减进货成本
项目净利  = 设备毛利 − 本项目工程费用合计       ← 再减实际支出
净利率    = 项目净利 / 合同总额 × 100%
```

- **设备毛利**用于看"卖货赚多少"（与零售毛利的算法一致）；
- **项目净利**用于看"这个工程到底赚多少"，是**老板要看的那个数**；
- 公共费用（不分摊到项目）**不进**任何单项目的净利，只进「本年工程开销」汇总与台账。

#### F10.2 费用类别（固定七类，不开放自定义）

| 值 | 类别 | 典型内容 |
| --- | --- | --- |
| 1 | 安装人工 | 安装师傅工钱、施工队结算、调试费 |
| 2 | 运输物流 | 物流费、货车、吊装、上楼费 |
| 3 | 辅材耗材 | 铜管、支架、冷媒、线材、保温 |
| 4 | 现场施工 | 打孔、开槽、脚手架、吊篮、开荒保洁 |
| 5 | 差旅招待 | 住宿、餐费、油费、过路费、招待 |
| 6 | 外包服务 | 设计、监理、第三方检测、图纸 |
| 7 | 其他 | 无法归类的小额支出 |

> 不开放自定义的原因：类别一旦可自定义，半年后必然出现"安装费/安装人工/安装工人工资"三个同义类目，汇总失去意义。七类覆盖工程 95% 支出，真归不进的选「其他」并在备注写清。

#### F10.3 字段清单

**入口**：项目详情「费用」Tab →「录入费用」

| 分组 | 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| 归属 | 所属项目 | 只读 | 是 | 从详情页进入时自动带入，不可改 |
| 费用信息 | 费用类别 | 单选（7 类） | 是 | 见 F10.2 |
| | 费用金额 | 金额 | 是 | > 0，2 位小数，上限 9,999,999.99 |
| | 发生日期 | 日期 | 是 | 默认今天，不可晚于今天（补录历史费用允许往前选） |
| 付款信息 | 付款状态 | 单选 | 是 | 1 已付 / 0 未付（挂账），默认已付 |
| | 付款方式 | 单选 | 已付时必填 | 1 微信 / 2 支付宝 / 3 公户 / 4 现金 / 5 其他。**仅备查，不改变任何账户余额** |
| | 付款日期 | 日期 | 否 | 默认同发生日期，未付时置灰 |
| | 收款方 | 文本(100) | 否 | 如"李师傅""顺丰物流"，便于对账 |
| 凭证 | 票据/凭证号 | 文本(50) | 否 | 收据号、发票号 |
| | 备注 | 文本(200) | 否 | 如"含 3 台加长铜管" |

**汇总区**（Tab 顶部）：`费用合计 ¥46,800 · 已付 ¥40,800 · 未付 ¥6,000` + 七类分类占比条（点击类别筛选明细）。

#### F10.4 规则

| 编号 | 规则 | 违反时 |
| --- | --- | --- |
| E1 | 费用金额 > 0，不允许录入 0 或负数 | 前端 + 后端拦截 |
| E2 | 已作废（状态 9）项目禁止新增费用 | 400 |
| E3 | 已结清（状态 5）项目**允许**录费用（师傅常在结清后才来结账），但弹提示"项目已结清，补录费用后净利会变化" | 提示不拦截 |
| E4 | 费用可编辑、可删除；删除为**软删除**，`operation_histories` 留 before 快照 | 无二次确认不给删 |
| E5 | 费用增删改后，项目 `expense_total` 与净利**同事务**刷新 | 事务回滚 |
| E6 | 工程费用**禁止**同时记入经营开销账户；经营开销也禁止记入工程费用 | 页面双向提示 + 评审拦截 |
| E7 | 付款方式选「公户」只是备查标记，**系统不改公户余额、不写公户流水** | 文案明确告知 |
| E8 | 费用不计入提成、不进工资条、不进零售看板与净利润口径 | 与 Q2/Q4 一致 |

> **⚠ 必须让老板知道的一件事**：如果工程费用真的从**公户**付出去，公户的实际银行余额会减少，但系统里不记这笔支出，于是公户账面金额会高于实际。你现有的"净额=余额"校验仍然成立（因为系统内自洽），但**账面余额与银行对账单会差出工程费用这一块**。
> 两个处理方式，二选一：
> 1. **（推荐）工程费用尽量走微信/支付宝/现金/私户**，公户保持"只进销售货款、只出进货成本"的纯净状态，公户对账永远能对上；
> 2. 若必须走公户，则每笔工程费用在备注里写清日期金额，月底用银行流水人工核对一次，把差额记为"工程支出"。
> 若你希望公户也能自动记工程支出，那是二期"工程资金打通"（Q1 的第二阶段），需要给公户增加"工程支出"流水类型并放开冻结规则，工作量约 +40%。

#### F10.5 验收标准

1. 录一笔安装人工 ¥3,000 后，Tab 汇总、概览盈利卡、项目净利三处数字同步变化；
2. 删掉这笔费用后，三处数字回到原值，操作历史可查到删除前快照；
3. 已作废项目无法录费用（按钮置灰 + 后端 400）；
4. 费用类别为「其他」时必须填备注（否则拦不住乱归类）；
5. 未付费用计入净利但不计入"已付"汇总。

### F11 工程费用台账（v1.1 新增）

**入口**：工程列表页右上「工程开销」→ `/admin/engineering/expenses`

**存在的理由**：项目内的费用 Tab 只能看到单个项目。老板需要回答两个跨项目问题——"今年工程总共花了多少"、"钱都花在哪类上"。另外有一类支出（共用的运输车、共用的施工队、投标保证金）**无法归属到某一个项目**，硬摊到某个项目会让那个项目的净利失真，所以必须支持"不分摊的公共费用"。

**顶部汇总条（4 个数）**

| 指标 | 口径 |
| --- | --- |
| 工程开销合计 | 筛选范围内全部费用合计（含公共费用） |
| 已付 | `pay_status = 已付` 合计 |
| 未付（挂账） | `pay_status = 未付` 合计 |
| 本年开销 | 本自然年发生额合计（不受筛选影响，固定口径） |

**类别分布条**：七类各自的金额与占比，点击即筛选该类别（再次点击取消）。

**筛选**：关键词（项目名 / 收款方 / 备注）｜项目（下拉，含"公共费用（不分摊）"）｜类别（多选）｜发生日期区间｜付款状态｜金额区间

**列表列**：发生日期｜类别｜所属项目（公共费用显示灰色 `公共费用` 徽标）｜金额｜付款状态｜付款方式｜收款方｜操作人｜录入时间｜操作（编辑 / 删除）

**公共费用录入**：本页「录入费用」按钮打开同一张表单，其中「所属项目」可选「公共费用（不分摊）」。此时费用只进台账与「本年工程开销」卡，不进任何项目净利。

**规则**
- 与 F10 共用同一张表、同一套校验，仅"所属项目"可空；
- 公共费用不允许挂到已作废项目（项目作废后其费用仍保留展示，但新增被拦截）；
- 台账只读展示 + 增删改，不做导出（一期）；二期按需加导出。

**验收标准**
1. 台账合计 = 各项目费用合计数之和 + 公共费用合计（可 SQL 复核）；
2. 点击某个类别后，列表与该类合计联动，清空筛选恢复；
3. 录一笔公共费用后，「本年工程开销」增加，但任何项目的净利**不变**；
4. 「公共费用」在列表中视觉上可明确区分，不会误认为某个项目的成本。

## 6. 关键业务规则汇总

| 编号 | 规则 | 违反时行为 |
| --- | --- | --- |
| R1 | 合同总额 = 设备总额 + 安装费 + 运输费 + 其他费用 − 折让 | 只读计算，不允许手改 |
| R2 | 付款节点计划合计 = 合同总额 | 签约拦截 |
| R3 | 节点累计实收 ≤ 计划金额；项目累计实收 ≤ 合同总额 | 登记拦截 |
| R4 | 已发货数量 ≤ 订购数量 | 出库拦截 |
| R5 | 成本单价为下单快照，不随后续商品改价变动 | 落库冗余 |
| R6 | 工程数据不写 `orders`、不写 `financial_logs`、不改 `accounts` | 代码评审拦截项 |
| R7 | 库存变动必须写 `inventory_logs`，禁止静默改 `store_stock` | 同上 |
| R8 | 所有写操作走事务 + 操作历史快照 | 同上 |
| R9 | 金额一律 `decimal(12,2)`，禁止 float 累加误差暴露到 UI | 同上 |
| R10 | 已结清项目金额字段锁定，仅可改备注/联系方式 | 后端拦截 |
| **R11** | **工程费用独立成表，禁止写入 `financial_logs` / `accounts`，禁止记入经营开销账户（id=7）** | 代码评审硬性拦截项 |
| **R12** | **项目净利 = 合同总额 − 设备成本 − 本项目费用合计；费用增删改同事务刷新 `expense_total`** | 巡检 SQL ⑥ 兜底 |
| **R13** | **公共费用（`project_id` 为空）不进任何项目净利，只进台账与「本年工程开销」** | 汇总口径写死 |
| **R14** | **费用删除为软删除，必须留 before 快照；已作废项目禁止新增费用** | 后端拦截 + 审计 |
| **R15** | **费用类别固定七类，不支持自定义** | 字典写死 |

## 7. 数据实体（概念模型）

> 具体字段类型、索引、外键在技术方案阶段定稿；此处只定义实体与关系，供产品设计引用。

```
EngineeringProject（工程项目）
├── EngineeringProjectItem[]（设备清单行）
├── EngineeringPaymentTerm[]（付款节点）
│     └── EngineeringReceipt[]（回款记录，挂在节点下）
├── EngineeringShipment[]（出库记录，可选：也可只落 inventory_logs）
└── EngineeringExpense[]（工程费用，project_id 可空 = 公共费用不分摊到项目）
```

## 9. 关键决策与待确认项

> 以下 5 条我已按"最稳妥、最小耦合"给出建议默认值。**未收到反对即按建议执行**，确认需求时一并拍板即可。

| 编号 | 问题 | 建议默认（我的选择） | 影响面 |
| --- | --- | --- | --- |
| **Q1** | 工程回款是否进资金账户台账（`financial_logs` / `accounts` 余额 / 公户流水）？ | **一期不进**。只在工程模块内记应收/实收，不碰账户余额，避免破坏"净额=余额"与公户冻结规则。二期若要把工程款进公户，单独做"工程款入账"动作 + 红冲能力 | 若选"进"，需追加资金链路设计，工期 +40% |
| **Q2** | 工程营收是否进经营看板 / 净利润口径？ | **一期不进**。工程在模块内独立核算，看板保持纯零售口径 | 若选"进"，需改看板、净利润、环比等 6+ 处 SQL |
| **Q3** | 工程出库是否扣门店库存？ | **扣**。否则工程卖了货库存不动，账实必错。新增 `log_type='engineering'` | 涉及库存流水页筛选类型扩展 |
| **Q4** | 工程单是否计算业务提成？ | **一期不做**。仅在项目上记录负责人 | 若要做，需定义规则（按回款额 % / 按毛利 %）并与工资条隔离 |
| **Q5** | 是否需要"投标/报备"中间态、竞争对手报价？ | **不做**。五态状态机（跟进→签约→供货→验收→结清）够用 | 若要，状态机与页面复杂度上升 |

**v1.1 追加决策（用户 2026-10-29 提出"工程开销必须与日常开销分开"后确定）**

| 编号 | 问题 | 结论 | 理由 |
| --- | --- | --- | --- |
| **Q6** | 工程开销记在哪？ | **独立成表 `engineering_expenses` + 独立页面（项目费用 Tab + 工程开销台账）**，不写 `financial_logs`、不改任何账户余额、不记经营开销账户 | 用户明确要求分开，否则项目净利算不出、日常费用率失真 |
| **Q7** | 无法归属到具体项目的支出（共用运输、共用施工队、保证金）怎么办？ | **允许 `project_id` 为空 = 公共费用**，只进台账与「本年工程开销」，**不摊入**任何项目净利 | 强行分摊会让每个项目的净利都不准；公共费用单独看更诚实 |
| **Q8** | 费用类别是否允许自定义？ | **不允许**，固定七类（安装人工 / 运输物流 / 辅材耗材 / 现场施工 / 差旅招待 / 外包服务 / 其他） | 开放自定义半年后必出现同义类目，汇总失效 |

**另需确认（低风险，默认按建议）**

- 项目编号规则 `GC-YYYYMMDD-NNN` 是否合适（可改前缀）？
- 工程单是否需要"打印报价单/合同"（一期不做，若刚需则纳入二期首批）？

### 9.1 确认结论（2026-10-29 用户确认）

| 编号 | 结论 |
| --- | --- |
| Q1 | **不进资金账户台账**。工程回款只在模块内记应收/实收，不写 `financial_logs`、不改 `accounts` 余额、不进公户流水。 |
| Q2 | **不进经营看板与净利润口径**。看板保持纯零售口径。 |
| Q3 | **扣库存**。出库扣 `store_stock` / `cloud_stock`，写 `inventory_logs`（`log_type='engineering'`）。 |
| Q4 | **不计算提成**（用户明确：工程单暂时不计算提成）。项目仅记录负责人，不产生 `commission_amount`，不进工资条。 |

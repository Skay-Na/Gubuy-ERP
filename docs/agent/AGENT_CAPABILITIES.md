# Agent 能力现状

## 已验证或已落地

- 原有聊天 Agent：管理员可发起多步只读业务查询；查询计划受显式工具注册表限制，运行追踪持久化；可创建支出/订单草稿，其中支出需人工确认。Provider 配置保持原状。
- 新增经营监测：固定规则读取真实商品库存和近 30 天有效订单商品销量，至少 3 件历史销量才评估潜在缺货；形成持久信号、任务、内部补货草案和活动。规则不调用 LLM，因此模型不可用时仍能工作。
- 新增结构化缺货目标与工作台。目标不代表授权。
- 页面记账和 Agent 支出确认使用相同的 `postBookkeepingEntry` 写入函数，统一账户锁、余额、关联订单和财务流水处理。

## 明确未实现

- 新增经营监测与原有聊天 Agent 尚未接入同一运行时；工作台是规则驱动，不声称由 LLM 自主推理。工具元数据的超时与输出 schema 尚未全部强制执行。
- 正式采购订单、供应商与交付周期、采购审批及预算、收货关联、付款、跨模块统一业务服务未完成。
- 多租户、库存积压/销售/毛利/采购异常监测、目标进度历史、任务取消与通用编排、事件 outbox 未完成。
- 本轮只验证内部补货草案闭环，不能称为完整真实采购闭环。

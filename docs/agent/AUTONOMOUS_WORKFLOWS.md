# 自主经营工作流

## 当前可验证的内部补货建议链

1. 管理员手动调用 `POST /api/ai/manager/scan`；或显式配置 `AGENT_MONITOR_ENABLED=1`，服务启动后及每 24 小时运行。
2. `MonitorService.Observe` 读取商品可售库存（主仓+门店+云仓，不含样机）与近 30 天正常订单的商品销量。
3. 至少卖出 3 件，且库存低于 7 天销量估计时形成 `low_stock` 信号；缺历史销量时不报缺货。
4. 同一商品已有开放信号时不重复创建；同一天去重键和唯一索引处理重复调度。
5. 信号与 `CREATED` 任务在同一事务持久化。处理器以条件更新认领任务，过期租约可恢复；尝试最多 3 次。
6. 重新读取当前商品库存后，生成 14 天目标库存的内部草案（单次建议最多 100 件）；事务中写活动并将任务设为 `SUCCEEDED`。缺供应商、交付周期、在途订单和预算的事实写在草案说明中。
7. 后续扫描发现库存不再符合规则时，信号与草案标为 `resolved`，追加活动。此动作仅说明库存风险规则已解除，不证明采购已完成。

此链没有审批、正式采购订单、供应商发送或付款。不能把 `AgentReplenishmentDraft` 当作采购订单。销售、毛利、积压和采购异常也尚未启用。

## 目标闭环

信号 → 数据解释 → 采购草案 → 审批请求 → 批准后重验 → 内部采购订单 → 收货并复用入库业务服务 → 验证目标库存 → 活动与结果。每一步持久化独立状态和幂等键，外部发送与付款另设授权。

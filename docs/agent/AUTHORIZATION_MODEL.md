# 授权与审批边界

当前系统用 JWT 区分管理员与员工，新增 `/api/ai/manager/*` 全部要求 `AdminAuthRequired`。现有 `AIAgentAction` 仅为一次性支出草稿确认；新补货草案没有正式提交接口。结构化目标与规则信号都不授予写权限。

| 动作 | 当前权限与影响 |
| --- | --- |
| 查看信号/任务/草案/目标/活动 | 管理员，只读 |
| 手动运行监测 | 管理员，只写 Agent 经营表，不写 ERP 订单、库存或资金 |
| 创建目标 | 管理员，只写 Agent 目标表 |
| 生成内部补货草案 | 规则处理器，不能提交采购 |
| 正式采购、外发、付款 | 当前无 API，不可执行 |

正式采购上线前必须建立独立审批表：绑定店铺、商品、供应商、数量/金额上限、预算、草案及数据版本、有效期、审批人、一次性消费键。批准时锁定审批与商品/采购记录，重新计算库存、在途量、价格和预算，并在同一事务中消费审批与生成采购订单。拒绝、过期、撤销均不可执行。支付须另设更高风险授权，本轮保持禁用。

目前旧业务表无租户字段；新增表固定 `tenant_id=single` 仅表达单店范围，不构成多租户保护。JWT 默认密钥和既有通用业务路由员工权限也应在生产安全审计中优先处理。

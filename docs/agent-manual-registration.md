# ERP Agent 业务说明书注册

Agent 启动时从 `erp-backend/controllers/agent_manuals/*.json` 加载业务说明书。理解用户问题时只看到模块 ID、标题和摘要；确定主题后，查询规划阶段才读取最多三个相关模块的详细规则。说明书为选择数据与口径提供背景，查询结果仍须由工具返回，标准指标仍由业务代码计算。

## 新模块接入

1. 在 `agent_manuals` 下增加 `<模块ID>.json`。无需修改 Agent 的主题枚举或主提示词；重新构建后会自动进入模块目录。
2. 填写 `id`（须与文件名一致）、`title`、`summary`、`keywords`、`datasets`、`rules`、`limits`。写明记录状态、时间字段、关联关系、关键指标的业务含义及不能直接推断的结论。
3. `datasets` 只允许引用 `ai_agent_data.go` 中已开放的数据集。新业务表需要先登记受控数据集并排除凭证、隐私字段；说明书本身不会开放数据库权限。
4. 涉及退款、工资、折扣、冲销等跨表或财务指标时，在报表代码中实现并测试正式计算口径。说明书只是解释，不能替代计算方法。
5. 运行 `go test ./controllers -run '^TestAgentManual'` 和相关业务问题测试。说明书引用未开放数据集、内容缺失或文件名与 ID 不一致会使 Agent 拒绝加载该目录。

示例：

```json
{
  "id": "returns",
  "title": "退货",
  "summary": "退货登记与退款进度",
  "keywords": ["退货", "退款"],
  "datasets": ["orders", "financial_logs"],
  "rules": ["退货登记和实际退款分别核对，不把已申请视为已退款。"],
  "limits": ["跨表对账需要经过验证的关联键。"]
}
```

说明书文件最多 8 KB，随应用版本发布。已有模块包括销售、工资提成、财务收支、库存、采购入库、考勤、国补回款、客户和员工。新页面如果沿用已开放的数据集，通常只需新增说明书；引入新表时还需登记数据集。新增高风险业务指标时必须实现并验证其计算逻辑。

## 本次验证

隔离测试库运行 `go test ./controllers -count=1`、`go vet ./controllers ./models ./config ./routers` 均通过。说明书测试覆盖自动发现、按主题加载、跨模块问题、未开放数据集拒绝和模型规划前注入。真实模型在隔离库完成销售对比、月份追问、指标纠正与库存概况四轮回归。当前工作区修改尚未发布到运行中的应用容器。

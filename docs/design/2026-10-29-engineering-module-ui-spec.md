## 1. 设计目标

1. **老板一屏看懂**：进工程列表 3 秒内知道"在做什么、钱收了多少、谁欠我钱、欠多久了"。
2. **台账替代 Excel**：所有金额有出处、可下钻、可核对，不需要另建表格。
3. **不制造新习惯**：操作路径与现有「订单管理 / 资金工作台」一致（列表 → 详情 → 弹层操作），员工零学习成本。
4. **不做装饰性设计**：一期不加图表动画、不做花哨看板，把信息密度和录入效率做上去。

## 2. 信息架构

### 2.1 菜单位置

侧边栏在「订单」之后插入「工程」，位置如下：

```
AI 店长 / 看板 / 收银 / 商品 / 订单 / 【工程】/ 记账 / 财务 / 历史操作 / 国补管理 / 员工 / 系统设置
```

- 图标：`Suitcase`（`@element-plus/icons-vue`）
- PC 菜单与移动端菜单（`menuItems` / `mobileMenuItems`）**同步新增**，移动端放在「订单」之后
- 仅管理端布局可见；`/terminal`（员工端）不新增任何入口

### 2.2 路由

| 路径 | 名称 | 组件 | 说明 |
| --- | --- | --- | --- |
| `/admin/engineering` | `EngineeringList` | `views/engineering/Index.vue` | 工程列表 |
| `/admin/engineering/expenses` | `EngineeringExpenses` | `views/engineering/Expenses.vue` | **工程开销台账（跨项目，含公共费用）** |
| `/admin/engineering/:id` | `EngineeringDetail` | `views/engineering/Detail.vue` | 项目详情，`?tab=overview|items|payments|shipments|expenses` |

> **路由顺序注意**：`/admin/engineering/expenses` 必须注册在 `/admin/engineering/:id` **之前**，否则 `expenses` 会被当成 `:id` 匹配进详情页。这是 Vue Router 静态路径优先的硬要求，写代码时容易踩。

- 详情页 Tab 用 **query 参数**驱动（`?tab=payments`），保证刷新与分享后定位不丢；
- 从列表进详情再返回，列表的筛选条件与页码需保留（用 `history.back()` 或把筛选写入 query，二选一由技术方案定，**交互要求：返回后筛选不丢**）。

## 3. 视觉与交互基础规范

### 3.1 金额

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 卡片大数字 | `¥` + 千分位，整数不显示小数 | `¥1,286,400` |
| 表格/明细 | `¥` + 千分位 + 2 位小数 | `¥12,860.50` |
| 负数（冲销） | 红色 + 负号 | `-¥5,000.00` |
| 待回款为 0 | 正常色显示 `¥0.00`，不加任何强调 | `¥0.00` |
| 空值 | 显示 `—`（em dash），不显示 0 | `—` |

输入统一 `el-input-number :precision="2" :controls="false"`，右对齐；直接输入 `12800` 自动格式化为 `12800.00`。

### 3.2 状态色（标签）

| 状态 | 文案 | 文字色 | 底色 |
| --- | --- | --- | --- |
| 1 | 跟进中 | `#64748b` | `#f1f5f9` |
| 2 | 已签约 | `#2563eb` | `#eff6ff` |
| 3 | 供货中 | `#d97706` | `#fffbeb` |
| 4 | 已验收 | `#635bff` | `#eef0ff` |
| 5 | 已结清 | `#15803d` | `#e8f7ee` |
| 9 | 已作废 | `#94a3b8` + 文字删除线 | `#f8fafc` |

标签形态：`border-radius: 999px`，`padding: 2px 8px`，字号 11px，不加边框。

### 3.3 逾期

三重信号，避免只看颜色：

1. 列表「待回款」数字下方加 11px 红字 `逾期 N 天`；
2. 行首左侧 3px 红色竖条（`box-shadow: inset 3px 0 #dc2626`）；
3. 节点表状态列显示红底「逾期」标签。

### 3.4 进度

- 回款进度 = 已实收 / 合同总额；发货进度 = 已发货台数 / 订购台数；
- `el-progress` 线型，高 6px，不显示百分比文字（数字在右侧单独显示，字号 11px）；
- 颜色：< 100% 且无逾期 → `#635BFF`；有逾期 → `#dc2626`；= 100% → `#15803d`。

### 3.5 状态反馈

| 类型 | 规范 |
| --- | --- |
| 加载（首屏） | 列表：骨架屏 6 行；详情：头部卡 + 内容卡骨架块；不使用全屏遮罩 |
| 加载（操作） | 按钮进入 `loading` 态，禁用重复点击 |
| 成功 | `ElMessage.success`，文案带结果数字（如"回款已登记，剩余待回 ¥86,000.00"） |
| 失败 | `ElMessage.error`，优先展示后端 `msg`；网络错误统一"网络异常，请重试" |
| 空态 | `el-empty` + 一句解释 + 一个主操作按钮（见 3.6） |
| 二次确认 | 破坏性操作（作废/删除/冲销/负库存出库）必须 `ElMessageBox.confirm` 或专用弹窗，确认按钮文字用动词（"确认作废"），不用"确定" |

### 3.6 空态文案

| 位置 | 主文案 | 副文案 | 操作 |
| --- | --- | --- | --- |
| 列表（无数据） | 还没有工程项目 | 工程机批量供货的合同、清单、回款都在这里管 | 新建第一个工程 |
| 列表（筛选无结果） | 没有符合条件的项目 | 试试放宽筛选条件 | 清空筛选 |
| 设备清单 | 清单为空 | 添加商品后才能签约 | 添加商品 |
| 付款节点 | 还没有付款节点 | 签约前需配置付款节点，且合计等于合同总额 | 添加节点 / 用默认比例填充 |
| 回款记录 | 暂无回款记录 | 到账后在这里登记 | 登记回款 |
| 出库记录 | 尚未出库 | 按清单行发货，出库会扣门店库存 | 新增出库 |

## 4. P1 · 工程列表页

### 4.1 页面骨架

```
┌─ 页头 ────────────────────────────────────────────────────┐
│ 工程项目                    [工程开销] [+ 新建工程]        │
│ 工程机批量供货：合同 · 清单 · 分期回款 · 发货               │
├─ 汇总卡（6 张）────────────────────────────────────────────┤
│ [在跟项目][待回款][逾期][本年实收][本年工程开销][平均净利率]│
├─ 筛选条 ───────────────────────────────────────────────────┤
│ [搜索框............] [状态▾] [类型▾] [负责人▾] [日期▾] [只看逾期] │
├─ 表格 ─────────────────────────────────────────────────────┤
│ 编号 │ 项目名称 │ 甲方 │ 负责人 │ 合同额 │ 已回 │ 待回 │ 进度 │ 状态 │ 操作 │
└────────────────────────────────────────────────────────────┘
```

### 4.2 页头

- H1：`工程项目`，`text-2xl md:text-3xl font-black text-slate-900`
- 副标题：`工程机批量供货：合同、清单、分期回款、发货`，`text-sm text-slate-400`
- 右侧按钮组：`工程开销`（`plain`，图标 `Wallet`，跳 `/admin/engineering/expenses`）+ `+ 新建工程`（`primary`）；移动端两按钮等分整行宽

### 4.3 汇总卡（6 张，`grid grid-cols-2 md:grid-cols-3 xl:grid-cols-6 gap-3`）

| # | 标题 | 主数字 | 副文案 | 可点击 |
| --- | --- | --- | --- | --- |
| 1 | 在跟项目 | N 个 | 合同额 ¥X（含跟进中预估） | → 筛状态=1/2/3 |
| 2 | 待回款 | ¥X | 覆盖 M 个项目 | → 筛选"待回款>0" |
| 3 | 逾期 | ¥X | N 个节点逾期 | → 打开"只看逾期" |
| 4 | 本年实收 | ¥X | 本年 N 笔 | → 无 |
| 5 | **本年工程开销** | ¥X | 含公共费用 · 点击看台账 | → 跳 `/expenses?date_start=本年1月1日&date_end=本年12月31日` |
| 6 | **平均净利率** | XX.X% | 已签约项目，未含公共费用 | → 无（tooltip 说明口径） |

样式：白卡 `rounded-2xl border border-slate-100 p-4 shadow-sm`；标题 12px `text-slate-500`；主数字 20px `font-black text-slate-900`（逾期卡数字用 `#dc2626`，**净利率为负时也用 `#dc2626`**）；副文案 11px `text-slate-400`。可点击卡片 hover 时边框转 `slate-200`。

> 第 5、6 张口径不同，容易让老板困惑，所以第 6 张副文案必须明写"未含公共费用"，并在 tooltip 里补一句：`净利率 = (合同额 − 设备成本 − 本项目费用) / 合同额，公共费用未分摊到项目`。

### 4.4 筛选条

| 控件 | 类型 | 宽度 | 说明 |
| --- | --- | --- | --- |
| 关键词 | `el-input` clearable | `flex-1`（最小 240px） | 搜项目名/编号/甲方/联系人/电话，300ms 防抖 |
| 状态 | `el-select multiple collapse-tags` | 180px | 六态，默认空=全部（不含已作废） |
| 项目类型 | `el-select` | 140px | 住宅精装/商业综合体/酒店公寓/政企学校/其他 |
| 负责人 | `el-select` | 140px | 员工列表（含外包） |
| 签约日期 | `el-date-picker daterange` | 260px | `YYYY-MM-DD` |
| 只看逾期 | `el-switch` + 文字 | auto | 开启后与状态筛选叠加 |
| 含已作废 | `el-checkbox` | auto | 默认不勾 |
| 重置 | `el-button text` | auto | 清空全部筛选 |

筛选变更立即查询（无需"搜索"按钮）；关键词走防抖。移动端筛选折叠为「筛选」按钮 + 抽屉。

### 4.5 表格列定义（PC）

| 列 | 宽度 | 对齐 | 内容 |
| --- | --- | --- | --- |
| 项目编号 | 140 | 左 | `GC-20261029-001`，`font-mono text-xs`，可复制 |

| 已回款 | 120 | 右 | 绿色系 `#15803d` |

### 11.4 API 命名约定（供技术方案对齐）

前端函数名与后端路径一一对应，风格沿用 `src/api/orders.js`：

```
fetchEngineeringProjects(params)      GET    /api/admin/engineering/projects
fetchEngineeringSummary(params)       GET    /api/admin/engineering/projects/summary
createEngineeringProject(data)        POST   /api/admin/engineering/projects
getEngineeringProject(id)             GET    /api/admin/engineering/projects/:id
updateEngineeringProject(id, data)    PUT    /api/admin/engineering/projects/:id
deleteEngineeringProject(id)          DELETE /api/admin/engineering/projects/:id
updateProjectStatus(id, data)         PUT    /api/admin/engineering/projects/:id/status
saveProjectItems(id, data)            PUT    /api/admin/engineering/projects/:id/items
savePaymentTerms(id, data)            PUT    /api/admin/engineering/projects/:id/payment-terms
createReceipt(id, data)               POST   /api/admin/engineering/projects/:id/receipts
reverseReceipt(id, receiptId, data)   POST   /api/admin/engineering/projects/:id/receipts/:rid/reverse
createShipment(id, data)              POST   /api/admin/engineering/projects/:id/shipments
fetchEngineeringExpenses(params)      GET    /api/admin/engineering/expenses
createEngineeringExpense(data)        POST   /api/admin/engineering/expenses
updateEngineeringExpense(id, data)    PUT    /api/admin/engineering/expenses/:eid
deleteEngineeringExpense(id)          DELETE /api/admin/engineering/expenses/:eid
```

> 费用走**独立路径** `/expenses` 而不是 `/projects/:id/expenses`，原因：公共费用没有项目 ID，两条路径会导致同一个表单要写两套提交逻辑，且台账页拉全量时还得区分。统一路径 + body/query 里带 `project_id`（可空）更简单。

## 13. 设计决策记录

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 清单与付款节点采用**整表编辑 + 一次提交**，不做逐行即时保存 | 行编辑会瞬间改变合同总额，而节点合计必须同步；整表提交才能保证"提交时刻金额自洽" |
| D2 | 详情页 Tab 用 query 而非嵌套路由 | 与现有 `ProductWorkspace` 不同，工程 Tab 间无独立权限与独立数据源，query 足够且返回行为更简单 |
| D3 | 出库用弹窗而非独立单据页 | 单次出库字段少（行 + 数量 + 仓），弹窗减少跳转；出库明细在 Tab 内可查 |
| D4 | 付款节点提供 30/60/10 等**快捷预设** | 工程业务 80% 用固定节点比例，减少重复录入 |
| D5 | 逾期用"红条 + 红字 + 标签"三重信号 | 老板常在手机上看，单靠颜色在阳光下不可辨 |
| D6 | 不引入图表 | 一期项目数量少（预计 < 100），汇总卡足够；图表留二期分析页 |
| D7 | 建档后自动跳详情 | 建档的直接目的是加清单，减少一次点击 |
| D8 | 所有破坏性操作按钮文字为动词（确认作废/确认冲销） | 避免"确定"造成误操作 |
| **D9** | **费用录入用弹窗、单独成 Tab，不混进「概览」或「回款」** | 费用是"往里花钱"，回款是"往回收钱"，同一个面板会让人看串；独立 Tab 也让"这个项目花了多少"一眼可查 |
| **D10** | **费用一个组件服务两个入口（项目内 / 台账），不写两套表单** | 两套表单必然出现校验规则分叉（比如一处允许未来日期、一处不允许），后期排查成本高 |
| **D11** | **公共费用在列表中用灰色 chip 明确标识，且按项目筛选时不出现** | 公共费用若混在项目行里，老板会误以为它属于该项目，净利怎么算都对不上 |
| **D12** | **不把公共费用按比例摊到项目** | 摊派规则（按台数？按合同额？）本身就是争议点，且摊完以后每个项目的净利都不再是"这个项目真实花的钱"。公共费用单独看更诚实 |

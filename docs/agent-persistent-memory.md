# ERP Agent 持久记忆

## 使用方式

- 在 Agent 对话中输入“记住：回答销售问题时先给结论”，系统会直接将这条明确要求保存到当前登录用户的记忆中。保存成功会返回确认；保存失败不会声称已记住。
- 点击 Agent 顶部的“长期记忆”，可以添加、查看、修改或删除用户资料、回答偏好和长期背景。
- 不必刻意说“记住”。“我喜欢先给结论”“回答太长了，简短点”“我负责门店经营”这类表达会触发模型归纳。成功对话累计每四轮也会回看近期对话；单次纠正当前查询不会自动变成永久偏好。
- 新会话提问时，Agent 会取回本用户的少量相关记忆。用户资料和回答偏好优先，长期背景按当前问题的中文相邻字匹配。每次最多带入八条、约 1200 字。

## 数据与边界

记忆保存在 `ai_agent_memories`，按登录用户名隔离。每个用户最多 100 条，每条最多 240 字。没有 embedding 服务或向量库。接口均经过管理员登录校验，更新和删除也验证归属。

记忆只帮助理解偏好和上下文。它不是系统指令、业务指标定义，也不是实时数据；回答销售、工资、库存等数字仍须查数据库。当前用户明确要求和系统计算口径优先。明显含密码、密钥、验证码或 Token 的内容会被拒绝。

自动归纳每次最多两条，只接受有用户原话依据的高置信候选，界面显示“对话归纳”与依据。重复内容不新增；已有自动记忆可以更新，手动或明确保存的记忆不会被自动替换。失败对话、未确认草稿、临时金额和日期不参与学习。删除后，删除之前的历史发言不再作为归纳依据，删除的内容不会被保留为隐藏记忆。

归纳使用当前配置的聊天模型，不使用 embedding。一次归纳最多等待 12 秒，失败时跳过；普通查询结果已先保存，不因归纳失败而变成查询失败。模型归纳仍可能误解表达，可通过记忆面板编辑或删除。

## 验证

隔离测试库验证了跨会话取回、相关背景筛选、用户隔离、显式保存、自动归纳、依据核对、临时数据排除、记忆替换、删除后的历史排除、编辑、删除和敏感内容拒绝。前端构建与移动端模拟接口交互已检查。运行中的生产容器尚未更新。

真实 DeepSeek 模型测试使用虚构表达：“先给结论、简短解释”和“回答太长了，简短点”分别成功归纳；“查上月销售额”没有保存为记忆。三项测试通过，单次调用约一到两秒。这是小范围场景验证，不保证所有表达都能一次归纳正确。

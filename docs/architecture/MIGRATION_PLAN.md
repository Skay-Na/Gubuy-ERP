# 历史迁移计划

旧计划中的“缺货→草案→审批”方向已于 2026-10-23 按门店运营要求撤下，不再属于当前实施目标。

# 渐进迁移计划

1. 审计、记录基线测试，备份数据库/配置；绝不清空卷或覆盖 Provider 密钥。
2. 添加独立 Agent 经营表和只读监测，默认关闭自动调度。生产部署前先在隔离 MySQL 上跑迁移、回滚演练。
3. 从高价值的库存读取与内部草案开始抽取业务服务，旧 HTTP/Agent 入口调用同一服务并保持响应契约；逐步扩至入库、商品定价、销售和资金。
4. 建立有作用域的工具注册、持久任务/租约、事件 outbox 和审批重验。旧聊天草稿仍按原接口运行，直到迁移测试通过。
5. 增加供应商、采购订单、收货及预算模型，关联已有入库事务；内部审批后只创建内部订单，供应商外发与付款分别授权。
6. 在隔离测试租户/数据库完成缺货→草案→审批→内部订单→收货→验证端到端测试，再打开功能开关。
7. 最后处理真正多租户：身份声明、所有业务表归属、唯一索引改造、历史数据回填、逐接口隔离验证。这是跨业务表迁移，不能通过新表字段替代。

每一步保持旧 API 与数据，采用可回退的小批次。破坏性 schema 变更及生产数据回填另行审查。

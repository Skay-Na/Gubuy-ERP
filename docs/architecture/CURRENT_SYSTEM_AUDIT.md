# 当前系统审计（2026-10-08）

## 证据范围

基于当前工作树的 `erp-backend/{main.go,config/db.go,models,controllers,routers}`、`src/{router,layout,views,components}`、`package.json`、`go.mod`、`Dockerfile`、`docker-compose.yml` 和现有测试。工作树在审计开始时已有大量未提交改动；本文描述的是这些文件的实际状态，不代表已发布版本。

## 实际架构与模块

- 前端是 Vue 3 + Vite + Element Plus + Pinia + ECharts，Vue Router 组织看板、收银、商品/入库/库存流水、订单、记账、财务、国补、员工、设置、图片导入、员工终端。Agent 是全局悬浮会话组件。
- 后端是 Gin + GORM + MySQL 单体。路由集中在 `routers/router.go`，业务和事务主要在大型 `controllers` 文件中。既有商品、库存、销售、采购入库、员工、资金/记账、国补、导入等业务。
- GORM `AutoMigrate` 在启动时运行；另有历史财务审计 SQL 脚本，但没有通用版本化迁移工具。审计开始时启动会在商品表为空时尝试插入三条演示商品；本轮发现无分类时会违反外键且错误被忽略，已改为仅显式开启 `ERP_SEED_DEMO_DATA=1` 时初始化，并检查写入错误。
- JWT 区分管理员和 `emp_` 员工身份。绝大多数业务路由使用通用 `AuthRequired`，部分路由额外要求管理员。数据库业务表没有 tenant_id，也没有店铺实体；目前是单店部署，不具备真正的多租户隔离。不能通过给新表加 tenant_id 就宣称已有租户隔离。
- Docker Compose 部署 app + MySQL，持久卷为 `gubuy-erp-mysql-data`。没有发现独立队列、调度、事件总线或统一业务审计基础设施。

## Agent 当前能力

- `ai_agent_controller.go` / `ai_agent_engine.go` 使用现有 Provider 配置，规划有限工具；支持最多数步跨数据集只读查询、证据汇总、草稿支出/订单、人工确认。运行记录、追踪、反馈、知识和长期记忆已有数据库模型。
- `ai_agent_data.go` 采用数据集/字段白名单及只读查询构造，有限时与行数限制。它不执行模型提供的原始 SQL。但白名单覆盖资金、员工等敏感业务数据；授权依赖管理员身份，缺少租户和细粒度数据域。
- `AIAgentAction` 是会话关联的 24 小时一次性草稿，已有确认事务；它不是可恢复的长期任务或通用审批。现有 `AIAgentRun` 是诊断索引，不是可调度、可中断、可重试的工作流状态。
- `GetAIAgentBrief` 按请求读取待办和库存，尚非主动、持久的经营监测。

## 核心问题与风险

1. 商品、入库、订单、资金规则大量位于 Controller。页面和 Agent 尚未共享完整的统一业务服务；同类操作有多个入口，回归风险较高。
2. 现有“采购”是入库和待确认入库，没有供应商、采购订单、交付周期、正式采购提交或采购预算模型。不得把入库申请或 Agent 文案冒充采购订单。
3. 无租户模型。若直接共享数据库给多店，现有查询和写接口会跨店；必须先迁移所有业务表及认证上下文，不能只保护新 Agent 表。
4. JWT 有内置默认密钥；若部署未设置安全密钥，会形成严重风险。通用业务路由的员工权限粒度也不足，需单独审计。
5. 启动自动迁移需要部署前备份和审查；演示种子现已默认关闭。不要在真实数据库直接跑开发测试。
6. 任务状态依赖会话/诊断记录，进程重启后无法可靠恢复多步骤操作。无统一幂等键、租约、事件投递和审批重验。
7. 利润口径与现金流/商品毛利不同；商品成本可能缺失。监测不得据此虚构毛利或建议。

## 可复用部分

现有 JWT、Provider 配置、只读受限数据查询、Agent 追踪、订单/入库事务、库存流水、前端请求封装、ECharts 与单体部署均可保留。下一步以新增、默认关闭的能力渐进接入，不批量重写已有控制器。

## 数据兼容性

新增表可用非破坏性迁移；现有业务表没有 tenant_id，不能安全回填多租户。已有密钥配置必须原样保留。未来抽取服务时需保持旧 API/事务/金额口径。低库存监测和补货建议已停用，历史数据仍保留供备份兼容。

## 第二阶段增量复核（2026-10-08）

- JWT 内置默认值已在当前工作树移除。应用在连接数据库之前校验环境变量 `JWT_SECRET`，要求至少 32 字节；Compose 无默认值。切换密钥会使既有令牌失效。
- AI 聊天、Agent 管理与 AI 店长接口要求管理员身份。补货草案审核 API 同样在管理员路由组中；审核服务校验状态和库存快照并记录审核主体。
- 普通聊天消息与监测任务已共享 `AgentWorkTask` 表；AI Agent 商品库存查询与规则监测的补货上下文共用 `services.RetailReadService`。这只是关键读取路径的抽取，不代表订单、入库、库存流水等 Controller 已整体服务化。
- 草案“approved”仅代表内部建议已确认。规则信号任务与聊天消息仍分离；原有商品/库存/销售/入库 Controller 尚未统一抽成共享业务服务；Agent Registry 也未覆盖 AgentNative 工具。
- 每日监测仍依赖进程内 ticker，用户可管理的数据库调度配置、暂停/恢复及自然语言长期任务尚未完成。
- 以上仅描述当前工作树，未暗示生产发布或完整第二阶段验收。细节见 `docs/architecture/PHASE2_IMPLEMENTATION.md` 和 `AGENT-NATIVE-PHASE2-REPORT.md`。

# Agent-Native 第二阶段实现记录

更新时间：2026-10-08。本文记录当前工作树已经落地的代码，不把规划或已有第一阶段能力算作本轮新完成内容。

## 本轮落地

- JWT 不再从代码默认密钥签发。`main` 在数据库连接前调用 `LoadJWTSecretFromEnvironment`，要求 `JWT_SECRET` 至少 32 字节；Compose 在变量缺失时拒绝展开。更换密钥会使已签发 JWT 失效，部署时须安排用户重新登录。
- AI 聊天、Agent 会话/记忆/动作/知识/Provider 设置、AI 店长工作台 API 都经过管理员权限中间件；新增草案审核路由也只注册在管理员组中。员工使用 `emp_` 身份时返回 403。
- 内部补货草案新增人工审核服务。服务在事务中锁定草案并读取当前库存；仅 `suggested` 状态允许处理。库存快照发生变化时持久标记 `stale` 并写入活动记录；确认、拒绝及数量调整记录审核人、备注和时间。此服务不创建订单、不改库存。
- AI 店长工作台显示草案状态，并允许管理员确认内部计划、调整建议数量或拒绝；错误时刷新后保留服务端反馈。
- 普通聊天回合现与消息记录在一个数据库事务中创建 `AgentWorkTask`，消息返回任务 ID；聊天窗提供工作台入口。聊天任务和监测任务共享同一表，`signal_id` 对聊天任务为空，任务按发起人、结构化目标/结果和幂等键留痕。旧 Agent 草稿确认会将关联任务从 `WAITING_APPROVAL` 推进为 `SUCCEEDED`。
- 新增 `services.RetailReadService`：Agent 商品库存搜索与 Monitor 补货上下文共用服务读取；可售库存仍为主仓+门店+云仓、排除样机，销量仍按 `order_status=1` 有效订单口径。
- 审核接口新增 Swagger 描述并重新生成 OpenAPI 文档。

## 沿用的已有能力

- 旧 Agent 的工具执行入口是 `controllers.agentExecuteTool`，先执行 `validateAgentToolPlan`，工具名须在 `agentToolRegistry` 中注册，再进入对应执行分支。
- 第一阶段 `agentnative.MonitorService` 负责规则观察、信号去重、持久任务租约和补货草案幂等；启动开关为 `AGENT_MONITOR_ENABLED=1`，由后端进程定时运行。
- 已有 API 读取 AgentNative 信号、任务、草案、目标和活动；聊天消息保存于独立的 Agent 会话消息表。

## 未完成的第二阶段核心项

- 聊天回合已创建并关联同一 `AgentWorkTask`，工作台也能显示目标/结果；但聊天运行本身仍同步执行，缺少逐步骤状态/租约恢复和进行中的任务详情。聊天与监测不是统一的工具执行器。
- 任务没有结构化步骤表、审批等待状态、持久调度配置、暂停/恢复 API 或跨进程调度租约。每日 ticker 是进程内 24 小时循环，不支持用户自定义计划。
- 旧 Agent 的白名单工具注册表尚未覆盖第一阶段工作流；商品基础读取和补货查询已共享服务，但库存流水、通用销售趋势、入库和状态变更能力未全面迁入共享业务服务。
- 草案审核具备状态幂等和库存快照冲突检测，但缺少“过期后重新计算”专用流程以及独立集成环境中的本轮执行记录。
- 尚未完成多工具 Agent 补货计划、信号触发 LLM 深度分析、调用预算/Token 用量记录、聊天任务详情跳转和长期任务交互。

## 安全与兼容性

新增的草案审核字段由 GORM `AutoMigrate` 兼容增加，不删除或重命名字段。`JWT_SECRET` 需部署环境显式提供，不能再依赖旧内置默认值；如果生产当前依赖该默认值，部署前应设置新的私有随机密钥，并接受已签发 token 失效。没有进行租户数据迁移。

不得把草案的“approved”解释成采购批准或订单提交。实际含义是管理员认可内部建议，采购、供应商沟通、付款和库存写入仍未实现。

## 3. 数据模型

### 3.1 字段定义（Product 新增 3 列，models/core_models.go Product 结构体）

```go
// 商品单独提成设置：0=跟随默认（按员工比例），1=按销售额百分比，2=固定金额每台
CommissionMode        int     `gorm:"type:tinyint;not null;default:0;comment:提成模式 0跟随默认 1按销售额百分比 2固定金额每台" json:"commission_mode"`
// mode=1 时的提成比例，0 < rate <= 1（decimal(5,4) 与 Employee.CommissionRate 同精度）
CommissionRate        float64 `gorm:"type:decimal(5,4);not null;default:0;comment:单独提成比例(0~1，仅模式1生效)" json:"commission_rate"`
// mode=2 时的每台固定提成金额
CommissionFixedAmount float64 `gorm:"type:decimal(10,2);not null;default:0;comment:每台固定提成金额(仅模式2生效)" json:"commission_fixed_amount"`
```

设计说明：
- 三个字段全部 `NOT NULL DEFAULT`，老商品落库即为 mode=0，**行为与现状完全一致**，无需数据迁移。
- mode 与 no_commission 的关系：`no_commission=true` 时后端强制 mode=0（互斥，no_commission 优先，见 §5 校验规则），不引入第四种模式值。
- 不在 OrderItem 上快照提成参数：提成在开单事务内一次算好写入 `orders.commission_amount`，此后历史订单永不重算（满足口径 4），商品后续改提成不影响已生成订单。

### 3.2 建表 SQL（生产 MariaDB 10.6 手工 ALTER 备用；本地/测试由 AutoMigrate 自动加列）

```sql
-- 幂等说明：MariaDB 10.6 无 ADD COLUMN IF NOT EXISTS，重复执行会报 1060，可忽略
ALTER TABLE products
  ADD COLUMN commission_mode TINYINT NOT NULL DEFAULT 0 COMMENT '提成模式 0跟随默认 1按销售额百分比 2固定金额每台',
  ADD COLUMN commission_rate DECIMAL(5,4) NOT NULL DEFAULT 0 COMMENT '单独提成比例(0~1，仅模式1生效)',
  ADD COLUMN commission_fixed_amount DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '每台固定提成金额(仅模式2生效)';
```

带默认值的 NOT NULL 列，现有全部数据自动填充 mode=0，不改任何现有数据。无索引需求（不按该字段查询）。

## 4. 计算公式（冻结，伪代码级）

### 4.1 判定优先级（写死，从上到下短路）

```
1. 整单 NoCommission（老板客户 req.NoCommission）      → 提成 = 0（现状保留）
2. 商会单 OrderType == 2                               → chamberCommissionCents(commissionableSales)/100
                                                         （资金池公式不变；商品单独提成对商会单无效）
3. EmployeeID == nil 或员工不存在                       → 提成 = 0（现状保留）
4. 其余订单                                            → 提成 = 默认部分 + 自定义部分（见 4.2）
```

项级排除（对默认部分和自定义部分同时生效）：
- `item.IsGift == true`（赠品，成交价=0）：销售额为 0，**且固定金额提成同样跳过**（赠品不发"每台固定提成"，这是本方案最易踩的坑）。
- `product.NoCommission == true`：整体排除，无论 mode 是什么（后端保存时已强制 mode=0，此处再兜底防御）。

### 4.2 分摊因子 K 与两段公式

沿用 `commissionableOrderAmount`（order_controller.go:53）的分摊思想，把订单级减免（折扣 / 以旧换新 / 国补）按销售额比例摊到各商品：

```
普通单（非国补）：K = actualPayAmount / totalAmount      （actualPayAmount 已扣国补、以旧换新、折扣，下限 0）
国补单：          K = 1                                  （国补单保持原销售额口径，与现公式 commissionBase=totalAmount 等价）
```

**开单循环内累计（替换 order_controller.go:504/643-646 的单变量累计）：**

```
totalAmount    += unitPrice * qty                       // 现有，不变
if !product.NoCommission:
    if product.CommissionMode == 0: defaultSales += unitPrice * qty   // 参与默认提成
    else:                           customSales   += unitPrice * qty   // 参与自定义提成
（同时把商品的 CommissionMode/CommissionRate/CommissionFixedAmount 存入 productMap 供提成段使用）
```

**提成计算段（替换 order_controller.go:734-749 非商会分支）：**

```
defaultPart = 0
if defaultSales > 0 and employee 存在:
    // 与现有 commissionBase * min(commissionableSales,totalAmount)/totalAmount 完全同构，只是分母内换成 defaultSales
    commissionBase = (isSubsidy ? totalAmount : actualPayAmount)
    defaultBase    = commissionBase * min(defaultSales, totalAmount) / totalAmount
    defaultPart    = moneyCents(defaultBase * employee.CommissionRate) / 100

customPart = 0
for each 订单项 item (product = productMap[item.ProductID]):
    if item.IsGift or product.NoCommission: continue        // 项级排除
    if product.CommissionMode == 1:
        itemSales = item.UnitPrice * item.Quantity          // 赠品已在前一行 continue，此处必 > 0
        customPart += moneyCents(itemSales * K * product.CommissionRate) / 100
    else if product.CommissionMode == 2:
        customPart += moneyCents(product.CommissionFixedAmount * item.Quantity) / 100

commission = defaultPart + customPart
```

说明：
- mode=1 逐项 `moneyCents`（=分）取整后累加，与现有默认提成同样的取整口径，避免累计浮点误差。
- mode=1 的分摊：Σ itemSales×K×rate = customSales×K×rate，与"先汇总再摊"在数学上等价，逐项写是为了语义清晰且便于测试。
- **固定金额（mode=2）不参与折扣分摊**——决策理由：mode=2 的业务语义是"每卖一台给固定提成"，类计件工资，与成交价无关；若随折扣缩水则不叫"固定"，店员也无法预期。折扣风险由店主设置固定金额时自行评估。mode=1 按销售额百分比则天然随折扣缩水，乘 K 与默认部分口径一致。

### 4.3 纯函数签名（order_commission.go）

```go
// CommissionItemInput 开单循环内逐项收集的提成输入快照
type CommissionItemInput struct {
    SalesAmount          float64 // item.UnitPrice * item.Quantity（赠品为 0）
    Quantity             int
    IsGift               bool
    ProductNoCommission  bool
    CommissionMode       int     // 0/1/2
    CommissionRate       float64
    CommissionFixedAmount float64
}

// calcOrderCommission 纯函数：输入订单项快照 + 金额信息 + 员工比例，输出订单提成（元，两位小数）。
// 不依赖 DB / gin，可单测。整单级判定（商会/老板客户）留在调用方，见 4.1 优先级。
func calcOrderCommission(
    items []CommissionItemInput,
    employeeRate float64,   // 员工不存在时传 0
    hasEmployee bool,
    totalAmount, actualPayAmount float64,
    isSubsidy bool,
) float64
```

调用方（order_controller.go 5.5 节）保持整单级三分支骨架不变：

```go
if req.OrderType == 2 {
    commissionAmount = float64(chamberCommissionCents(commissionableSales)) / 100   // 不动
} else if req.EmployeeID != nil && !req.NoCommission {
    commissionAmount = calcOrderCommission(customItems, employee.CommissionRate, true,
        totalAmount, actualPayAmount, req.IsSubsidy)
} else {
    commissionAmount = 0                                                            // 不动
}
```

## 5. 接口契约（冻结）

### 5.1 通用约定

沿用现状：响应体 `{"code": 200, "msg": "success", "data": ...}`；鉴权沿用现有中间件；商品创建/更新为全量字段语义（UpdateProduct 走 map 全量更新），**三个新字段在创建与更新时都是必传语义**（不传视为 0 / 跟随默认）。

### 5.2 DTO 字段表（CreateProductRequest / UpdateProductRequest 同步新增）

| 字段名 | json | 类型 | 校验规则（后端，违规返回 400） | 默认 |
|---|---|---|---|---|
| commission_mode | `commission_mode` | int | 仅允许 0/1/2，其他值 → `"提成模式非法"` | 0 |
| commission_rate | `commission_rate` | float64 | mode=1 时必填且 0 < rate ≤ 1 → `"请设置提成比例（大于0且不超过1）"`；mode≠1 时服务端强制置 0 | 0 |
| commission_fixed_amount | `commission_fixed_amount` | float64 | mode=2 时必填且 > 0 → `"请设置每台固定提成金额"`；mode≠2 时服务端强制置 0 | 0 |

补充约定：
- **no_commission 互斥**：`no_commission=true` 时服务端无条件强制 `commission_mode=0, commission_rate=0, commission_fixed_amount=0`（静默归零，不报错），保证"无提成"优先级最高、数据不出现非法组合。
- 团队下达口径为"fixed 必填 ≥0"，本方案**收紧为 > 0**：fixed=0 等价于跟随默认（mode=0），允许它会产生语义无效的配置，禁止。若需保留 ≥0 口径由主理人裁决，改动仅一行校验。
- UpdateProductRequest 的更新 map 增加 `"commission_mode" / "commission_rate" / "commission_fixed_amount"` 三个键（归零逻辑在构造 map 前完成），mode=0 的更新会同时把另外两列清零。

### 5.3 商品列表返回

`GET /api/products` 返回 `models.Product` 原生 JSON，新增三个 json 字段（`commission_mode` / `commission_rate` / `commission_fixed_amount`）自动带出，后端无需额外处理。**不新增任何接口**。

### 5.4 错误码

| 场景 | code | msg |
|---|---|---|
| mode 非法 | 400 | 提成模式非法 |
| mode=1 未给比例 / 越界 | 400 | 请设置提成比例（大于0且不超过1） |
| mode=2 未给金额 / 负数 / 0 | 400 | 请设置每台固定提成金额 |
| 其余（重名、404 等） | 现状不变 | — |

## 7. 兼容性与公共影响

1. **老商品零感知**：mode=0 时 `customSales=0`，公式退化为 `commissionBase * defaultSales/totalAmount`，而 defaultSales ≡ 原 commissionableSales，结果与现逻辑逐分一致（测试用例 1/16 回归锁定）。
2. **商会单不动**：OrderType=2 分支一行不改，`chamberCommissionCents` 资金池公式不变。
3. **历史订单不重算**：提成只在开单时计算一次并落 `orders.commission_amount`；无任何回填/重算任务。
4. **手动修改接口仍是最终覆盖**：2117-2165 不动。
5. **operation_history 中文标签**（operation_history_controller.go）：
   - 552 字段表追加：`{key:"commission_mode", label:"提成模式"}`、`{key:"commission_rate", label:"单独提成比例"}`、`{key:"commission_fixed_amount", label:"每台固定提成"}`
   - 1006 `operationFieldValue` 新增 case：`commission_mode` → `0:跟随默认, 1:按销售额百分比, 2:固定金额每台`；`commission_fixed_amount` 加入 1011 行货币字段列表；`commission_rate` 复用现有 1052 行百分比格式。
6. **AI 导入开单等旁路入口**：凡走 `CreateOrder` 的入口自动生效；无其他写 `commission_amount` 的入口需排查（已确认）。

## 9. 风险与难点

| 风险 | 影响 | 应对 |
|---|---|---|
| mode=2 赠品误发固定提成 | 赠品成本外又多付提成 | 公式里 IsGift 先于 mode 判定短路 + 测试用例 5 锁死 |
| UpdateProduct 全量更新把老商品提成清掉 | 商品编辑一次即丢提成配置 | 前端 handleEdit 回填三字段；后端 map 全量写入属既有语义，前端回填即可，不加特殊兼容 |
| 纯函数与调用方参数错位（K 口径传错） | 提成算错 | 纯函数只收 totalAmount/actualPayAmount/isSubsidy，K 在函数内算，调用方无自由度 |
| MariaDB 10.6 AutoMigrate 加列在生产耗时 | 部署窗口抖动 | products 表量级为商品档案（千级），加列秒级；仍提供手工 ALTER 备用（§3.2） |
| 商会单误配商品提成后被误认为生效 | 用户困惑 | 前端商品表单提示文案："商会订单不使用商品单独提成"；后端商会分支天然不受影响 |
